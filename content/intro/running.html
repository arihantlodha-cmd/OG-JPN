Installing and running OG-JPN#

Installation#

OG-JPN needs Python 3.12 or 3.13 and OG-Core 0.24.6 or later.

With uv:

git clone https://github.com/arihantlodha-cmd/OG-JPN.git
cd OG-JPN
uv sync --extra dev

Or with pip:

git clone https://github.com/arihantlodha-cmd/OG-JPN.git
cd OG-JPN
pip install -e ".[dev]"

Demographic data#

Japan’s fertility, mortality, and population come from the UN World Population Prospects (country code 392). No setup is needed: Japan is in OG-Core’s offline data mirror, EAPD-DRB/Population-Data, so the model runs without a UN API token. A free UN Data Portal token, saved as ~/.config/og/un_api_token.txt, makes OG-Core pull the live data instead.

The pension-age (analysis_retirement_age*.py) and replacement-rate (analysis_replacement_rate*.py) reforms follow the same pattern.

run_ogjpn_tpi.py takes --initial-wealth data (the default: Japan’s observed wealth-by-age profile, see Initial distribution of household wealth) or --initial-wealth ss (OG-Core’s steady-state proxy).

Transition-path runs use Dask for parallel computation and are memory hungry. On a laptop, run them one at a time.

Using the calibration in your own scripts#

Apply the calibration with ogjpn.calibrate.update_specs rather than p.update_specifications: the model is anchored to yen, and OG-Core’s validation rejects a yen-scale starting guess for the currency factor, so update_specs sets that one value directly.

from ogcore.parameters import Specifications
from ogcore.execute import runner
from ogjpn.calibrate import Calibration, update_specs
from ogjpn.constants import START_YEAR

p = Specifications(baseline=True)
p.update_specifications({"start_year": START_YEAR})
update_specs(p, Calibration(p).get_dict())
p.baseline_dir = p.output_base = "./OUTPUT_BASELINE"
runner(p, time_path=False)
